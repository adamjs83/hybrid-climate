# Entities

This page lists every entity Hybrid Climate creates, the attributes on the climate entities, the diagnostic entities, and the Repairs issues. Read it when you build a dashboard or automation, or when you wonder what an entity is for.

Home Assistant generates entity ids, so yours can differ from the examples here. Find the real id in **Settings → Devices & Services → Entities**, or through the `get_config` service (see [Services](reference/services.md)). Do not build ids by hand.

## What you get

| Entity | One per | What it is for | Example id |
|---|---|---|---|
| Master climate | Home | Whole-home control with preset modes. Lives on the device "Hybrid Climate - <master name>". | Generated from the master name; unique id `hybrid_climate_<entry_id>_master` |
| Zone climate | Zone | Per-zone control of mode and target temperatures. Fresh installs get this id; existing installs keep their ids. | `climate.hybrid_climate_<zone_id>` |
| Saved temperatures | Zone | Number entities for the Home, Away, Sleep and Vacation heating targets and the Home, Away, Occupied, Unoccupied, Sleep and Vacation cooling targets. Configuration category. See [Presets and modes](configuration/presets-and-modes.md). | `number.basement_heating_target_home` (generated from the names) |
| PI gains | Zone with PI heating, or with cooling stages | Five heating PI numbers and five cooling PI numbers you can tune live. | Generated by Home Assistant |
| Zone sensors | Zone | **Temperature** is the temperature the zone controls to. Zones with PI regulation add **Heating regulated setpoint**, and zones with time-of-use add **Time-of-use state**. Both of those are in the Diagnostic category. | Generated by Home Assistant |
| Hold switch | Zone | On while the zone holds its current temperatures. Turning it off resumes the saved temperatures. | `switch.basement_hold` (generated from the zone name) |
| Restore control button | Zone | Runs one restore pass over the zone's devices. The same pass runs automatically after a settled master mode change. It is in the Configuration category. | Generated by Home Assistant |
| Diagnostic entities | Zone, device, or home | Read-only sensors for history and graphs (see below). | Generated by Home Assistant |

The hold switch has the attributes `hold_since`, `hold_until`, `held_heat` and `held_cool`. See [Holds](concepts/holds.md). The restore pass is explained in [Idle and restore](concepts/idle-and-restore.md).

The **Temperature** sensor on each zone is the control temperature. There is no separate "control temperature" entity, so you get one history stream, not two.

## Diagnostic entities

These entities sit under each device's **Diagnostic** section and are hidden from dashboards by default. They update when the integration recalculates (no polling) and are read-only.

| Entity | Attached to | Reports |
|---|---|---|
| Reason | Each zone | The main status reason code, for example `within_target`, `heating_demand` or `unknown`. The attribute `codes` lists every code currently recorded. |
| Temperature spread | Each zone with two or more indoor sensors | The spread across the zone's smoothed sensor readings, in your Home Assistant temperature unit. The attribute `method` is the configured aggregation method. If a zone drops to one sensor, the entity that already exists stays and shows unavailable. |
| Stage | Each zone | The active stage, for example `heating_stage_2`. It shows `heating_stage_1_opportunistic` during an opportunistic run and `none` when the zone is idle. |
| Uncontrolled | Whole home, one per configured device | Problem sensor. On when a device reports heat or cool but no zone owns it, or when its mode or setpoint was changed outside Hybrid Climate. Attributes: `reported_mode`, and `manual_override`. |
| Outdoor fallback active | Whole home | Problem sensor. On when a backup outdoor sensor, not the primary, supplies the reading. |
| Outdoor source | Whole home | The entity id that currently supplies the outdoor reading. The attribute `primary` is the configured primary sensor. |

`manual_override` is `null` or an object in this shape:

```json
{"commanded": {"mode": ..., "target": ...}, "reported": {"mode": ..., "target": ...}, "since": "<ISO time>"}
```

## Master climate attributes

| Attribute | Meaning |
|---|---|
| `version` | Integration version |
| `outdoor_temperature` | Current outdoor temperature |
| `zone_count` | Number of configured zones |
| `zones_heating` | List of zones currently heating |
| `zones_cooling` | List of zones currently cooling |
| `zones_idle` | List of idle zones |
| `active_conflicts` | List of active conflict descriptions |

## Zone climate attributes

| Attribute | Meaning |
|---|---|
| `master_mode` | Current master mode |
| `current_stage` | Active stage, for example `heating_stage_1` |
| `active_devices` | Devices currently running |
| `blocked_devices` | Devices blocked by conflicts |
| `time_in_stage` | Seconds in the current stage |
| `sensor_values` | Raw sensor readings |
| `sensor_smoothed_values` | Smoothed sensor readings |
| `regulation_offset` | Heating PI offset (when PI regulation is on) |
| `accumulated_error` | Heating PI integral term |
| `regulated_setpoint` | The setpoint actually sent to regulated devices |
| `cool_regulation_offset` | Cooling PI offset. It is 0 or below, and 0 until a cooling-PI device runs. |
| `cool_accumulated_error` | Cooling PI integral term. It is 0 until a cooling-PI device runs. |
| `cool_regulated_setpoint` | Cooling PI setpoint. It is none until a cooling-PI device runs. |

## Repairs issues

Conditions that need your attention appear under **Settings → System → Repairs**. Each issue names the entity and tells you where to go. Each one clears itself when the condition ends.

- A zone whose sensors have failed for longer than the grace period.
- A stage device that has been unavailable for longer than the device outage grace.
- A thermostat under manual override.
- A stage where none of the devices can serve it.
- A change applied through `set_config` whose saved settings are not active ("Saved Hybrid Climate settings are not active").

The logbook entry for each `set_config` apply stays.
